## Task 1 — Understanding the Problem

1. **Environment.** A static two-dimensional grid warehouse. Each cell
   is either free (`.`), an obstacle (`#`), the starting position (`S`),
   or the goal (`G`). The environment is fully observable, discrete,
   deterministic, static, and single-agent.
2. **Goal of the agent.** Reach the cell marked `G` from the cell
   marked `S` without ever occupying a `#` cell.
3. **Actions.** `Up`, `Down`, `Left`, `Right`. Each action changes the
   agent's position by one grid cell. An action is invalid if it would
   leave the grid or step onto an obstacle.
4. **Information the agent must maintain.** The grid, the goal cell,
   the agent's current position, the frontier of positions still to be
   explored, and the set of positions already visited (together with
   enough information — e.g. a `came_from` map — to reconstruct the
   path once the goal is reached).
5. **Why goal-based and not simple-reflex.** A simple-reflex agent
   chooses an action from the current percept alone; it has no notion
   of "I am trying to reach `G`". Our agent plans a sequence of actions
   leading to `G` using an explicit goal predicate (`current == goal`)
   and reasoning over future states. That makes it goal-based.

### Think About It — doubled warehouse

BFS on a 4-connected grid is still complete and optimal, but the number
of expanded states grows roughly with the area, so memory for the
frontier and the visited set grows accordingly. The time to find a path
also grows. For much larger maps, an informed strategy such as A* with
Manhattan distance would expand far fewer states (see the Search Lab)
and would therefore be preferable.

## Task 2 — Agent Design

- **Environment:** `grid: list[str]` parsed from the ASCII map.
- **Current state:** the agent's `(row, col)` position.
- **Goal:** the `(row, col)` of the cell marked `G`.
- **Available actions:** the four moves `Up`, `Down`, `Left`, `Right`.
  An action is applicable only when the resulting cell lies inside the
  grid and is not an obstacle.
- **Decision-making component:** uninformed graph search (BFS). The
  frontier is a FIFO queue; a `came_from` dictionary records the parent
  and action used to reach each discovered cell so that the final path
  can be reconstructed once the goal is popped.

Block diagram (text form):

```
+-----------+     percept     +------------------+
|  Grid /   |---------------->|   Goal-based     |
| Warehouse |                 |   agent          |
+-----------+   action         |------------------|
     ^        <----------------|  state: pos      |
     |                         |  goal:  G        |
     |                         |  model: grid     |
     |                         |  planner: BFS    |
     +-------------------------+------------------+
```

## Task 3 — Prompt Engineering and Validation

Prompt actually used (summarised):

> *Write a well-documented Python program implementing a goal-based
> agent for the warehouse navigation problem shown below. The agent
> starts at `S` and must reach `G` on a 2-D grid of `.` and `#` cells.
> It can move Up/Down/Left/Right one cell at a time. Use breadth-first
> search; print the action sequence, the number of states expanded,
> and the path drawn on the map. Explain why BFS is appropriate.*

Answers to the questions in Task 3:

1. **Did the LLM generate a working program on the first attempt?**
   The first draft parsed the map, ran BFS, and found a path, but it
   printed only coordinates. Reconstructing an *action* sequence
   required a follow-up prompt in which I asked that the parent link
   store both the previous cell and the action name.
2. **How can the prompt be improved?** Spell out the output format in
   advance ("print the move names in order"), ask for a reconstruction
   helper, and demand test cases including an unreachable goal.
3. **What search algorithm did the LLM choose?** BFS.
4. **Why?** Because every move has unit cost: BFS is complete and
   returns a shortest path, and the state space is small enough that
   the uninformed strategy is adequate. (An LLM typically also knows
   that BFS is the canonical starting point for pedagogical grid
   problems.)

## What was LLM-generated / what I changed

- *Generated by the LLM:* the overall skeleton of the BFS loop and the
  initial parsing of the ASCII map.
- *Changed by me:* storing `(parent, action)` in `came_from` rather
  than only `parent`, so that the action sequence can be reconstructed;
  tightening the `passable` bounds check; adding `render_path` for
  visual verification; writing the test suite in `tests.py` (trivial,
  unreachable, shortest-path).
- *Verified by me:* ran `warehouse_agent.py` and inspected the drawn
